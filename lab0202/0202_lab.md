## 6. Контрольные вопросы

### 1. Что такое ветка в Git и как она реализована?

Ветка — это независимая линия разработки. Технически ветка представляет собой указатель на определённый коммит. При создании нового коммита указатель перемещается на него.

### 2. Чем отличаются merge и rebase?

Merge объединяет изменения двух веток и обычно создаёт отдельный коммит слияния. Rebase переносит коммиты одной ветки поверх другой, формируя новую последовательную историю.

### 3. Что такое конфликт слияния?

Конфликт возникает, когда Git не может автоматически объединить изменения, например когда разные ветки изменили одни и те же строки файла.

### 4. Как разрешить конфликт? Какие маркеры используются?

Нужно открыть конфликтующий файл, вручную выбрать или объединить нужные изменения, удалить служебные маркеры и сохранить файл.

Маркеры конфликта:
- `<<<<<<< HEAD` — начало текущей версии;
- `=======` — разделитель версий;
- `>>>>>>> branch` — конец изменений другой ветки.

После исправления выполняются `git add` и команда завершения merge или rebase.

### 5. Чем отличаются reset и revert?

`git reset` перемещает указатель текущей ветки на другой коммит и может изменять индекс и рабочую директорию. `git revert` создаёт новый коммит, отменяющий изменения выбранного коммита, сохраняя историю.

### 6. Чем отличаются fast-forward и трёхстороннее слияние?

Fast-forward применяется, если текущая ветка не содержит новых коммитов относительно объединяемой ветки. Git просто перемещает указатель вперёд.

Трёхстороннее слияние использует общего предка и последние коммиты двух веток, создавая коммит слияния.

### 7. Для чего нужна release-ветка в Git Flow?

Release-ветка предназначена для подготовки версии к выпуску. В ней выполняются финальные исправления, проверка и подготовка релизной версии.

### 8. Как отправить все локальные ветки на удалённый сервер?

Для отправки всех локальных веток используется команда `git push --all origin`.

### 9. Почему rebase может быть опасен при работе с общими ветками?

Rebase изменяет историю коммитов, создавая новые идентификаторы. Если перебазировать общую ветку, это может нарушить историю других участников и привести к конфликтам при синхронизации.
